## Session summary
valkyrie-sparring-1 reported that the reconcile stage ("WHETHER THE NUMBERS ADD UP")
flagged five correct formula results as mismatches in a stats-heavy spar. Fixed the
cause, two related weaknesses and a test that failed on this machine, then released
0.6.1 to PyPI.

## Decisions made
1. **Root cause was the extraction schema, not the arithmetic.** The extractor could
   only label a relation sum/product/count/percent_of, and a missing operation
   defaulted to sum, so the model filed formulas as sums. Added `difference`,
   `expression` (formula transcribed as written, evaluated in code by a literal-only
   AST evaluator) and `other` (not checked). The model still only extracts; Python
   still decides.
2. **"Not checked" over a guess.** A missing operation, `other`, an expression that
   won't evaluate, or a `sum` whose own quote carries a formula operator
   (`· × ÷ √ ^ ± ² ³ ⁴`) is unverifiable, never a mismatch. `/` and Markdown `**`
   are excluded from that guard so unit rates and bold totals are still checked.
3. **Margin measured against the figures.** The old `max(|s|, |c|, 1.0)` floor let
   any figure under 1 agree with almost anything. Now: 0.5% of the figures, or half
   a unit of the last digit shown.
4. **Precision read from the quote.** JSON drops trailing zeros (0.120 → 0.12), so
   the allowance comes from the numeral in the aggregate quote that equals the
   stated value (handles `1,200`, `6e-5`, `6×10⁻⁵`, `%`). Falls back to the number.
5. **Ledger permission test skips where chmod is ignored** (Bart chose option 1 over
   changing TMPDIR). It probes its tmp dir and skips only the mode assertion.
6. **0.6.1** (patch): bug fixes to an existing check, no new interface.
