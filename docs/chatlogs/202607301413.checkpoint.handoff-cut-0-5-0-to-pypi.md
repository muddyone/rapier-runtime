## What is actually in the release

**The bug.** `backend_literature` ran only a Crossref *bibliographic search* and gated every
candidate on a cited-surname match. A bare identifier contains no surname, so it could never
match, and the fallthrough was `GROUNDED_REFUTED / "fabricated"`. A bare DOI and a bare arXiv
id — the two most authoritative citation forms there are — were the two that always failed.
`cite_check` exposed `lookup_crossref_doi` and `lookup_arxiv` the whole time; the backend
called neither.

**The fixes.** Identifier-strength resolution (DOI → arXiv → search, decisive both ways); a
Crossref miss discriminated by source class instead of blanket-refuted; new `law`
(CourtListener, anonymous) and `patent` (Google Patents) backends; evidence unioned across
every identifier a reference supplies rather than raced; and a Proposer-side
`traceability_gate` so the framing step's own citations are grounded (RM §10.1/§13.1) —
previously verification was Resolver-only, so a Proposer could cite a nonexistent source and
the run reported clean.

**Two traps recorded in the commits**, both worth not re-introducing: patent kind codes are
not guessable (`US4405829B1` and `US9876543A` both 404 while the same patents resolve bare),
and a length-capped regex silently truncated `2,999,999,999` into the *real* patent `2999999`
and verified a fabrication.

## Caveats

- **Do not re-run `loom-promote --adopt`.** It regenerates the overlay conf and blanks
  hand-set fields; it wiped the `repo=` URL once already. The conf is at
  `~/.loom/overlay-projects.d/rapier-runtime.conf` and is safe to hand-edit — just don't
  re-promote after.
- **The PyPI upload is irreversible.** A version can be yanked, never replaced or re-used.
  That is why every gate in `loom-deploy-prod.sh` exists.
- **The PyPI token is read from 1Password at run time** (`PyPI — rapier-runtime
  (bart.niedner)`, vault `Sparring Framework`, field `live`) into the process environment. It
  is never written to disk, echoed, or logged. Keep it that way.
- **The vendored engine has a sibling copy in loom** (`skills/shared/spar/scripts/` and
  `skills/shared/cite-check/scripts/`). They are meant to stay in sync and had silently
  drifted — three divergent copies of `verify_grounding.py` existed before today. Both are now
  aligned (`loom c956f9c1`), with one deliberate difference: `CONTACT_EMAIL`. Check the pair
  when either changes.
- **This project was built on a 17-commit-stale checkout earlier today** because nothing
  pulled it. That is precisely what the Loom registration fixes — but it means: run
  `/sync-now` before trusting local state.
